# 03 — Risk Analysis

Severity: **S1** = can make the device unreachable or lose configuration; **S2** =
feature breaks or data is wrong; **S3** = cosmetic/operational.

| # | Risk | Severity | Evidence | Mitigation | Residual |
|---|---|---|---|---|---|
| R1 | Restoring a whole `wireless`/`network` file clobbers unrelated user config (the old mesh backup does exactly this) | S1 | `backup_restore` in 2.7.12 copies whole files | Scoped restore: type-specific section merge (`backup.sh` `merge_wireless`, `merge_network`); full restore only when the user asks for Full and confirms the scope | Medium: section merge of `network` is limited to mesh-owned sections |
| R2 | Node/client LAN address change cuts the management link | S1 | `apply_node_lan` + watchdog in 2.7.12 | Reuse watchdog: snapshot LAN state, apply, wait for LAN up, roll back on timeout; UI warns and requires confirmation | Cannot fully protect against a wrong address the *user* typed on a static config (watchdog covers) |
| R3 | Restore makes the network unreachable mid-operation | S1 | reload of network/wireless | Pre-restore backup; apply from snapshot copy; background worker verifies LAN + at least one wireless device; automatic rollback from snapshot on failure; UI states explicitly that recovery may require LAN/console | Hardware behaviour 待验证 |
| R4 | Two managers write `wireless` concurrently | S2 | both plugins exist | Single `flock` run lock; legacy service disabled during migration; all writes in one engine | If the user re-enables the legacy service manually, races return (documented) |
| R5 | Writing `bss_transition`/`ieee80211r` on an unsupported wpad takes the radio down | S1 | `wnm_supported` comment in source | Keep the whole-string NUL probe; never write 802.11v without it; 802.11r only when enabled by user | 802.11r support itself is not probed (same as upstream behaviour) — documented |

| R11 | Backup contains secrets (WiFi keys, DAWN shared key) | S1 | DESIGN §10.8 | Dir 0700, files 0600, never log key material, UI never renders keys, download warns, optional passphrase encryption | Unencrypted backups remain sensitive; stated in UI |

| R13 | UCI section copy loses list-vs-scalar semantics | S2 | merge implementation | `uci export <cfg>.<sec>` parser distinguishes `option`/`list`; values with embedded tabs/newlines are rejected at backup time (logged, section skipped) — documented | Exotic values |

| R17 | Upload/download paths expose arbitrary files | S1 | new feature | Download uses ACL file read limited to the two backup directories; upload path whitelisted and re-validated as tar; no user-provided download path reaches the backend | `cgi-download` follows the ACL, not the UI |
| R18 | Package removal leaves the legacy service disabled | S2 | migration disables it | `postrm` re-enables if it was disabled by us and the old package still exists; configuration and backups are never deleted | If the old package was removed earlier, nothing to restore |

| R21 | rpcd plugin JSON escaping bugs corrupt results | S2 | shell JSON output | Use `jshn` for output and `jsonfilter` for input; all free text passes through `json_add_string`; a test drives `wm_call` with quotes/newlines | Requires jshn/jsonfilter (standard on OpenWrt 24.10+) |

| R23 | A mesh apply fails halfway and leaves partially committed UCI | S1 | old `enable_meshassistant` wrote section by section with no rollback | `mesh_apply` takes a private snapshot of every file it may touch before changing anything, reverts staged UCI and restores the snapshot on failure, then reloads and reports the rollback in `op.json` and the event log; a snapshot that cannot be created stops the apply before any change | A commit failure on real hardware is 待验证 |

| R35 | The unified diagnosis produces a false alarm or hides a real failure behind a summary | S3 | aggregation of four independent sources | Findings keep their source and original code, are sorted errors first, and the raw cards with the underlying values stay on the same page; the report is advisory and never blocks a save or a restore; a source that cannot be read is shown as unavailable instead of being counted as healthy | Thresholds for load and memory are product choices, not firmware limits |

| R37 | FT over DS is selected while the access points have no wired path, so fast transition stops working | S2 | hostapd has one FT transport per BSS | The form defaults to over-the-air (`ft_over_ds=0`) and explains that DS requires every AP of the mobility domain to be reachable over the wired network; only an explicit `meshassistant.ft_over_ds=1` writes `ft_over_ds=1`, and both the roaming apply and the mesh AP writer read the same `ft_over_ds_value()` | A mismatch between APs is not detected; hostapd behaviour is 待验证 |

## Operation-level safety rules implemented

1. Every state-changing worker takes the run lock (`flock -n`), does `uci commit`
   per touched config, and records start/end in the log.
2. A pre-change backup is created before: mesh apply/disable, dumb AP, restore,
   the migration from Mesh Assistant, and (through the view) before saving
   wireless interfaces when auto backup is on.
3. A failed restore restores the snapshot copy of every touched file, and a
   failed mesh apply reverts staged UCI and restores its own snapshot.
4. Every restore checks the archive and the merged result with
   `config_check_syntax`; a file that does not parse is never committed.
5. No code path deletes a backup it did not create in this format, and no migration
   step deletes or rewrites a legacy archive.
6. No code path writes to `/etc/config` from the frontend; only validated ubus
   methods and the `uci` form path (user-driven, unchanged from 1.0.0) do.
